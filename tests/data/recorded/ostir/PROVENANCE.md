# OSTIR 1.1.3 recorded runs (M2-16; GIAP_SPEC.md §7.1.1, §7.1.6)

- Tool: OSTIR 1.1.3 (GPL-3.0; run as a separate process only, never imported) with ViennaRNA 2.6.4
  (`run.log`: "Running OSTIR version 1.1.3 (with Vienna version: 2.6.4)"), `giap-ostir`
  micromamba env (`workflow/envs/ostir.yml`; env lock hashes in `versions.txt`).
- Recorded by `scripts/slurm/record_tools.sbatch` on FarmShare (barley-01 / wheat-01, 9 CPUs),
  2026-10-15, into `$GIAP_ROOT/recordings/ostir/{sim100k,k12_mg1655,nissle1917}/`.
- Command (`command.txt`): `ostir -i ostir_input.csv -o ostir.csv -j 9`.
- Input: `ostir_input.csv` built by `scripts/dev/record_tools_inputs.py ostir <bakta>.json` from the
  recorded Bakta 1.12.2 full-DB JSON (`$GIAP_ROOT/recordings/bakta_full/<sample>/bakta/<sample>.json`;
  sha256 sim100k `d28c8781…99cf`, k12_mg1655 `13c54a89…374c`, nissle1917 `49dbc4dc…256f`).
  The header is `id,seq,start,end,anti-Shine-Dalgarno` (accepted by OSTIR 1.1.3; resolves M2-16 Q1:
  the input column is `id`, OSTIR's output column is `name`). Anti-SD `ACCTCCTTA` in all three.
- Checked 2026-10-15 (test author): applying the M2-16 geometry to `parse_bakta_json(...)` genes
  in §6.5 order (every gene incl. sORFs and pseudogenes) reproduces all three recorded
  `ostir_input.csv` files byte for byte.

Excerpt rows are copied verbatim, in file order, with the original header. `genes.tsv` (written
by the test author from `parse_bakta_json` on the same Bakta JSON) lists, for the rows present,
`locus_tag, feature_type, contig, contig_length, topology, start, end, strand, start_codon`
(0-based half-open, as `Gene.interval`). `command.txt`, `run.log`, `versions.txt` are the
recorder's files for the full run.

No recorded run has rows for one id at several `start_position`s: with `start = end = 51` OSTIR
only scores the requested start. Several candidates (example 7) and clipped windows (examples 3, 5)
are therefore covered by hand-written inputs in the unit and property tests only.
