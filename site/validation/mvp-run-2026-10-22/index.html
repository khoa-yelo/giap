    Surprising: no gene is detected, and every downstream test is empty¶

    All 87 genes have detected = false, and p_detect is constant at 0. Because of that: - every pair has test = none, and the flags are too_few_op_pairs;unestimated; - operon_flags.tsv is empty; - every autocorrelation row is not_estimable; - islands.tsv is empty; - operons.tsv has detected_frac = 0 for every TU.

    1864792 showed the same picture (86/86 undetected), which was attributed to the ID mismatch. #163 fixed the mismatch, but zero detection remains. Root cause, from the outputs and code:

    • gene_q_value is 0.011765 = 1/85 for every gene with evidence.
    • giap.genetable.detection computes the picked-protein FDR as (D(t)/f + 1) / T(t). There are no winning decoys, so D = 0, and T = 85, which gives a floor of 1/85.
    • stats.alpha.identification is 0.01 (the default; resolved_config.yaml is the same as 1864792 apart from bakta_json).
    • So no gene can reach q <= 0.01 on a genome with fewer than 100 evidenced genes. The q-threshold rows in detection_summary confirm this:
    q threshold genes detected
    0.001, 0.005, 0.01 0
    0.02, 0.05, 0.10 85

    There are 83 2-peptide detections.

    This is a property of sim100k's size together with the +1 correction and the default alpha. It is not a pipeline failure. But it means that sim100k with default config cannot exercise any detection-dependent statistics (M4 regions, M5 autocorrelation and islands, M6 operon tests). The M4-21 golden used alpha 0.05, where 85 genes are detected.

    Decisions for the lead (this run changed nothing): - use a larger simulated genome for the MVP run, or - set an alpha of 0.05 for this validation through a run config, or - accept that example 1 ("every test none") holds here only trivially.

    Comparison with the sim truth¶

    sim100k is a global null for abundance. The default proteomics path draws giapsim.proteomics.gene_log_abundance, which is i.i.d. N(1, 1.5) on the natural-log scale. So there is no TU co-expression, no positional autocorrelation, no ori-ter gradient and no region effect. M4's TU/AR(1) expression model is opt-in and is not used by SIM100K.

    So the expected number of true rejections is 0, and every family returned 0: - 65 pair tests: 0 at q ≤ 0.1. About 3.3 p ≤ 0.05 are expected by chance; 5 were observed. - 79 Moran's I and join-count rows: 0. - islands: 0. - slopes: every CI covers 0.

    Example 1 ("every test none or nothing significant") now holds non-trivially.

    What looks odd, statistically¶

    1. Within-operon |Δ log2| is large: median 2.0 and up to 8.8 for truth TU-mates. That is what i.i.d. abundance implies (SD of a difference ≈ 1.5·√2/ln 2 ≈ 3.1 log2). The within-operon t fit therefore models null noise. On this sim the discordance test cannot show power; it can only show calibration. Measuring power needs a sim with TU-coherent abundance.
    2. TU calls are coarse: 20 called TUs against 35 in the truth.
    3. Of the 67 called OP pairs, 22 straddle a truth TU boundary.
    4. |Δ| for those 22 (mean 2.48) is no different from truth TU-mates (2.72), again because of the i.i.d. abundance.
    5. The 13 conflict_terminator_in_operon flags are mostly right: 12 of the 13 flagged pairs cross a truth TU boundary. The terminator evidence catches real UniOP/TU merge errors.
    6. The gene q-value is a single value (1/85) for all detected genes. The tier table puts 0 genes at q ≤ 0.01 and 85 at q ≥ 0.02. This is the 1/T floor from section 1. Detection is all-or-nothing between α = 0.01 and 0.02 on this genome.
    7. Detectability cannot be checked here. It is constant in both runs: 0 detected at α = 0.01, and 85 of 87 at α = 0.05.
