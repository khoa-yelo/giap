    Running GIAP¶

    giap run checks the inputs (preflight), then runs the analysis through Nextflow. It writes the output tree described in Outputs. This page covers the common options. The CLI reference lists every option with its type and default.

    giap run --genome genome.fna --peptides peptides.tsv --db-dir /path/to/db --outdir out

    Check the inputs first¶

    giap preflight --genome genome.fna --peptides peptides.tsv --abundance abundance.tsv --outdir out

    giap preflight runs the same input checks as the first step of giap run, in seconds, and runs nothing else. It writes out/preflight/preflight.json and preflight.md. giap run repeats the checks and stops before Nextflow starts when one fails. In run mode, preflight also checks that the tools and databases of the chosen modules and profile are installed.

    Inputs¶

    Option Input
    --genome genome FASTA (required)
    --peptides generic peptide table
    --proteins protein FASTA
    --abundance protein abundance table
    --annotation Bakta JSON, GFF3 or GenBank
    --reference-peptides same-strain database peptides for the same spectra
    --replicon-depth contig, mean_depth table
    --outdir output directory (required)
    --db-dir database directory of giap setup; default $GIAP_DB_DIR

    The formats are described in Inputs.

    Modules¶

    --modules takes a comma-separated list chosen from core, mobile, bgc and function. All four run by default.

    Module What it adds Needs from giap setup
    core annotation and context layers, mapping, the gene table, detection, context statistics, operons, variants, novel ORFs and determinants; always on, even when it is not listed Bakta DB (checked even with --annotation bakta.json) and Promotech models; contaminants recommended (they label contaminant peptides)
    mobile prophage and plasmid regions from geNOMAD --genomad
    bgc biosynthetic gene clusters from antiSMASH --antismash
    function COG, GO and KEGG categories, detection enrichment, abundance GSEA --go --kegg --cog 
    giap run --genome genome.fna --peptides peptides.tsv --modules core,function --outdir out

    A module that is switched off writes no files, and the manifest lists it under modules_off. Later steps run without it. For example, the region tests then have no prophage or BGC regions.

    Analysis options¶

    Option Values Config key
    --genome-relation related (default) or same: is the proteomics from this exact strain? genome_relation
    --abundance-type ibaq, top3, maxlfq, intensity, unknown abundance.type
    --abundance-scale auto, log2, linear abundance.scale
    --abundance-missing median, exclude, min, zero, mean abundance.missing
    --promoters targeted (upstream windows; default) or genome (genome-wide) annotation.promoters.mode
    --terminators terminatornet (default) or transtermhp annotation.terminators.tool
    --add-bactermfinder also run BacTermFinder (opt-in) annotation.terminators.bactermfinder
    --sensitivity basic (default), full, off output.sensitivity
    --parquet also write Parquet twins of large tables output.parquet

    Every option above is a shortcut for a configuration key. Any key can be set with --config FILE or --set key=value (repeatable; the value is YAML). The order of precedence is: defaults, then the config file, then the command-line flags, then --set. An unknown key exits with code 1. The resolved values are written to OUT/resolved_config.yaml and to the manifest. All keys are listed in the configuration reference.

    Resources and execution¶

    Option Default Meaning
    --threads 16 (config threads) threads; the upper limit per task
    --memory 64.GB memory for the workflow
    --profile farmshare,apptainer comma-joined Nextflow profiles (see Install)
    --resume off resume a stopped run in the same --outdir

    Resuming. --resume passes nextflow -resume to Nextflow. Tasks whose inputs did not change are taken from Nextflow's cache in OUT/work. Give the same inputs and options as the run you resume. Nextflow's work directories can reach tens of GB per run (GIAP_SPEC.md §3.9). Delete OUT/work once the run is complete and you no longer need to resume it.

    The --executor option is a developer feature. It is described in the Developer guide, not here.

    Seeds and reproducibility¶

    Every random draw (permutations, bootstraps, decoy shuffles, cross-fitting folds) comes from one master seed. --seed sets it, and the default is the config value seed. Each step derives its own stream from the master seed and the step name. The same inputs, options and seed therefore give byte-identical tables. The seed is recorded in run_manifest.json.

    giap run --genome genome.fna --peptides peptides.tsv --seed 42 --outdir out_seed42

    Publication mode¶

    --publication raises the resamples to 10,000 permutations and 10,000 bootstrap draws (stats.permutations, stats.bootstrap, and the determinants null determinants.permutations). It also records the setting in the manifest. The default is 1,000 of each. Permutation p-values are (1 + b)/(1 + B), where b counts the permuted statistics at least as extreme as the observed one, out of B permutations. With B = 1,000, the smallest attainable p-value is therefore about 0.001. Publication mode lowers that floor. The run takes longer; measured runtimes are on Runtimes.

    Strict mode¶

    --strict turns preflight warnings into a failure: the run stops before Nextflow starts, with exit code 3. Without --strict, warnings are reported in preflight/preflight.md and the run continues. giap preflight --strict behaves the same way. giap report --strict exits with code 3 when the report exceeds its size budget.

    Exit codes¶

    Every giap command uses the same exit codes:

    Exit code Meaning
    0 success
    1 invalid input: preflight errors, a bad option or an unknown configuration key
    2 environment error: a tool, database or model is missing (for example nextflow not on PATH, or a giap setup source that cannot be reached)
    3 warnings were raised and --strict was given
    4 a pipeline step failed
    5 internal error (a bug); the message asks you to report it

    When a step fails, the manifest names it and points to its log: failed_step and failed_log, from OUT/logs/trace.tsv. An internal error writes OUT/logs/internal_error.log. Please report it at https://github.com/khoa-yelo/giap/issues with the command line and that log.

    Logs¶

    OUT/logs/ holds the following:

    • events.jsonl: structured warnings and events, one per line;
    • trace.tsv, timeline.html and nf_report.html: Nextflow's task trace and reports;
    • <step>.log for a step that failed.

    --log-level (DEBUG, INFO, WARNING, ERROR) sets how much is printed to the terminal.
