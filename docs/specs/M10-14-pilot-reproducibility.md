## The runbook format (`validation/pilot/reproduce.md`)

Prose is free; five structures are fixed, because the tests and `reproduce_check.py` parse them.

**1. Header** (the first line):

```text
<!-- reproduce: status=draft|final freeze_commit=<40-hex>|pending a3_branch=cascadia|fallback|pending -->
```

**2. `## Inputs`**: one table, columns exactly `id | path | sha256 | recorded_in`.

- `id` is unique (`[a-z0-9_]+`). `path` is repository-relative for committed files, or starts with
  `$GIPPA_ROOT`, `$GIPPA_DATA_DIR` or `$GIPPA_DB_DIR` for FarmShare files.
- `sha256` is 64 lower-case hex. A `.d` run directory, which has no single hash, is listed through
  its archive (manifest `sha256`) and its `analysis.tdf` (M10-02 `provenance.json`), as two rows.
- `recorded_in` names one or more committed files, `;`-separated, each containing that exact hash
  string. Committed inputs list a second file, never only themselves (a file is not its own record).
  For a FarmShare file whose hash is recorded only on FarmShare (a `provenance.json`), `recorded_in`
  is that path, and only `verify` can check it.

**3. Steps**: one `### S<n> <title> (M10-<nn>)` heading per step, in execution order. Under it:

- exactly one `Job:` line:
  `Job: script=<path> name=<gippa-…> partition=<p> qos=<q> cpus=<n> gpus=<n> mem=<m> time=<t> constraint=<c|-> array=<a|->`,
  plus `children=nextflow:<queue>x<cpus>cpu` for `gippa_run.sbatch` (its task jobs), or `Job: none
  (session)` for a step that runs in the allocation in under ten minutes (only `static` checks and
  `git` commands);
- a fenced `bash` block with the exact command(s), environment variables included;
- `Reads:` a comma-separated list of input `id`s; `Writes:` paths.

**4. `## Evidence`**: columns `step | label | job | state | exit | elapsed | maxrss | node | commit`.
One row per accepted job, plus superseded attempts with `state` `superseded`.

**5. `## Outputs`**: columns `id | path | sha256 | recorded_in | kept`. `kept` is `yes` or
`deleted:<UTC date>` (after the clean-up). These are the converted tables, the per-arm
`report.html`, `compare.html`, the freeze `metrics.json`, and each arm's **gate digest** (below).

**A3 branches.** `## A3` holds two subsections, `### A3-cascadia (status: active|inactive)` and
`### A3-fallback (status: active|inactive)`, each with its own steps (S-numbered in the same
sequence). The `inactive` one keeps its commands for the record, and its steps have no Evidence
rows.

**Gate digest** of a run directory: the sha256 of the UTF-8 text made of one line
`<sha256>  <path>\n` per **gate** file (M10-06's TE7 class: `tables/**`, `mapping/**`, top-level
`annotation/*`, `plots/data/**`, `schemas/datapackage.json`), sorted by path. It is one hash that
stands for every R7 table of an arm, and it reveals no content (question L2).

## Freeze gate (before any freeze run)

The lead declares the freeze when **all** of these hold, and records the declaration in PROGRESS
(a "freeze window" line, like M10-12's benchmark window):

1. Merged on main: M10-03 to M10-07, M10-09 and M10-10 (or M10-11a/b), M10-12; the hardening of
   the index ("What M10 depends on that is not merged"): M7-11b, the ADR-0049 flags, M7-13b, M7-15,
   M8-15, M8-16, and the M9 report PRs (M9-16, 16b, 17, 19/20, 26). An item may instead be
   **deferred by the lead** with a PROGRESS line naming it and saying what the report will lack
   (question L3). M6-12 part C (#292) is already merged.
2. The main checkout (`/home/classes/bios/270/khoa/giap`) is fast-forwarded to `origin/main` and
   clean; its HEAD is the freeze commit **F** (40 hex), written into the runbook header.
3. **The main checkout stays at F** until the last freeze run's head job has ended. `gippa_run.sbatch`
   runs the main checkout; fast-forwarding it during the window would run later arms on other code.
   Merges to `origin/main` may continue; only the checkout waits (question L4).
4. `pilot_reproduce_check.sbatch` has exited 0 at F (the next section).
5. The R14 sum S of running and pending `gippa-*` CPUs is ≤ 14 at each GIPPA submission (one arm:
   8 × 14 + 2 = 114 CPUs, M10-04). Arms run one at a time.

## The clean-up (`pilot_cleanup.sbatch`)

`DRY_RUN=1` (the default) prints the plan and writes `plan.tsv`; `CLEAN=1` executes it. Everything
goes to `$GIPPA_ROOT/pilot/cleanup/`: `plan.tsv` and `DELETED.tsv` (`path`, `kind`, `bytes`,
`sha256` for regular files ≤ 10 GB, else `NA`, `action`, `utc`, `job`).

**Preconditions** (exit 2, nothing deleted):

- `$GIPPA_ROOT` is set and every target path resolves (`realpath -e`) inside it; no target is a
  symlink (it is listed as `skipped_symlink` and left alone);
- the freeze evidence exists: every `$R/evidence/*.json` has `failures: []`, the compare JSON too,
  and `$GIPPA_ROOT/pilot/metrics/freeze-<F7>/metrics.json` exists;
- `verify-<F7>.json` has `failures: []` and its re-conversion results are all recorded;
- no `gippa-*` job that reads pilot paths is pending or running (`squeue -u $USER -h -o '%j'`
  matched against `gippa-run-*pilot*`, `gippa-run-freeze-*`, `gippa-diann-*`, `gippa-entrapment`,
  `gippa-denovo`, `gippa-pilot-*`, `gippa-bench`), the job's own ID excluded;
- no target is an Inputs row of the runbook or an Outputs row with `kept = yes`.

## Edge cases

- **A re-run that differs.**
  - *Freeze vs pass 1:* expected whenever code changed between them. Not a failure. The runbook
    lists pass-1 jobs as `superseded` evidence, and the report reads only the freeze directory.
  - *Freeze A2 vs its replicate (S10):* TE7 at F. A `fail` is investigated as M10-06 requires
    (`## Diagnosis: TE7` with a cause class). It does not block the clean-up: the evidence rules
    concern exit codes and provenance. `known_lapack` is reported as in M10-06 L9.
  - *Re-conversion differs:* example 8.
  - *A later reproduction:* the "Verify" section. A different CPU class may give `known_lapack`.
  - *DIA-NN re-search differs:* not done here. A later reader who re-runs S5 may hit M10-06's L3
    non-determinism; the runbook says so and names the converted-table hash as the reproduction
    target.
- **An expired allocation.** The session ends while freeze jobs run: they are batch jobs; their
  IDs are in PROGRESS and `ATTEMPTS.tsv` before polling; the evidence is computed afterwards from
  the outdirs and `sacct`. A head-job `TIMEOUT` (2 days) is M10-04's `resume-infra`: same command
  plus `--resume`, same commit, not an R9 attempt. A clean-up job killed by its own time limit is
  example 10. The freeze window line stays in PROGRESS until the last head job ends, so a new
  session does not fast-forward the checkout.
- **A changed image digest.**
  - *DIA-NN:* example 5. No search is re-run here, so nothing waits; the mismatch is a Blocked row
    for Khoa, and the runbook states that S5 cannot be repeated until the authentic image returns.
  - *GIPPA tool containers:* the freeze manifests' `tools[]` (`container_digest`,
    `conda_lock_hash`) must be equal across all freeze arms; `reproduce_check.py` compares them
    from the evidence step and fails `tools_differ:<tool>`. A difference means an image changed
    under the same commit (an Apptainer cache replaced, or a digest-less tag). The arm that
    differs re-runs fresh after the cache is fixed. A difference from pass 1 is recorded, not failed.
  - *Cascadia/Casanovo weights or env lock:* `verify` hashes them against `a3_assets.tsv` (or
    M10-11a's manifest). A mismatch does not block the GIPPA A3 run, which reads only the
    converted table, but the runbook marks the de novo step unrepeatable until it is resolved.
- **The freeze commit moves.** A bug found during the freeze is fixed in its own PR. F becomes the
  new main HEAD F′, and **every** arm's accepted attempt must end at F′. M10-04's resume rule
  (`resume-downstream` only when the diff touches the failed step and later ones) may be used per
  arm (question L4).
- **Empty input.** A runbook with no `### S` heading or an empty Inputs table: `static_check` gives
  `no_steps` / `no_inputs`. A clean-up plan with nothing to delete: exit 0 and an empty ledger. A
  peptide table with no target rows cannot reach S8 (M10-03 summary rules).
- **Ties.**
  - Two accepted attempts of one arm: the latest passing one wins (M10-04).
  - The same hash on two Inputs rows with different paths (a file copied): allowed and reported
    as `duplicate_hash:<id>,<id>` (a warning).
  - Two `recorded_in` files that disagree cannot both contain the runbook's string: that row fails
    `not_recorded` for one of them.
  - Two steps with the same S-number: `duplicate_step`.
- **Circular/linear genomes, strands.** Not touched: the runbook moves files and hashes them. The
  genome's topology tags are part of its committed bytes, so the genome hash covers them. For the
  fallback, the UTI89 genome must carry its tags (M10-11a); `verify` checks the header tag as
  `entrapment.py` does for Nissle.
- **Partial deletes and symlinks.** Targets are resolved with `realpath -e` and must lie under
  `$GIPPA_ROOT`. Symlinks are skipped, so a link into another user's space cannot be followed.
  `rm` is never given a glob that spans directories (`set -f`; explicit paths from the plan).
- **The contract tests after the clean-up.** M10-03's `slow` full-report test skips (the reports
  are gone); the 1,000-row sample test keeps running (step 5 keeps the samples). The runbook says so.
- **Disk.** If `$GIPPA_ROOT` is over 400 GB at the freeze, the work directories of pass 1 and the
  bench runs (plan step 1) may be cleaned **before** the freeze runs, with `PLAN_ONLY=1-1`
  (question L9); the §3.9 deletions (steps 2 and 4) always wait for S-check.
