- **Memory and CPUs.** Both partitions enforce `MaxMemPerCPU = 4000 MB`, so a job that asks more
  memory than CPUs × 4000 MB is given more CPUs (M10-02 PR #293, S1). M10-08's scripts ask
  `--mem=32G` with 8 CPUs (→ 9 CPUs) and `--mem=64G` with 8 CPUs (→ 17 CPUs). M10-10 states the
  real counts on the command line: `--cpus-per-task=8 --mem=32000M` for step 1 and
  `--cpus-per-task=16 --mem=64000M` for step 2. **Sizing rule for step 2, fixed before the runs:**
  if the smoke run's `MaxRSS` (M10-08, `sacct`) is ≤ 21 GB, step 2 uses `--cpus-per-task=8
  --mem=32000M` (1.5 × 21 GB ≈ 32 GB) and the three jobs take 24 CPUs; otherwise the 16/64000M of
  the table. The rule and the value used go into the README.
- **Peak.** Steps 1–2: 16 + 48 = 64 CPUs and 3 GPUs (WT_1's Cascadia job can start while WT_2/WT_3
  convert). Step 4 alone: 114 CPUs. Steps 2 and 4 never overlap (114 + 48 > 128).
- **Before each `sbatch`** the lead sums the CPUs **and the GPUs** of every running and pending
  `giap-*` job of every agent (`squeue -h -u $USER -o '%j %C %b %T'`, names `giap-*`). Submit only
  if CPUs + the job's ≤ 128 and GPUs + 1 ≤ 4; otherwise wait and re-check (polls ≤ 10 min apart).
  Never lower `--threads` of step 4 to fit (M10-04 Q1).
- **Time limits.** Step 2's 4 h is the smoke run's wall time × 4, rounded up, with a floor of 4 h.
  A TIMEOUT gets one resubmission at 24 h, then R9 (as M10-08). Step 4 follows M10-04's failure
  table.
- Every job ID, purpose and log path goes under PROGRESS › In progress at submission; after each
  job ends, `sacct -j <id> --format=JobID,JobName,State,Elapsed,MaxRSS,NodeList,AllocCPUS,AllocTRES`

## The three Cascadia runs

- **All three runs are fresh M10-10 runs**, from one commit, one env lock and one weights file, so
  A3 has uniform provenance (question Q1). WT_1 is run again although M10-08 already ran it: the
  smoke output stays under `A3_cascadia/` as the verdict's evidence. The two WT_1 `.ssl` files are
  compared and the result is reported (byte-identical, or the data-row counts and the number of
  distinct folded peptides in each). GPU inference need not be bit-reproducible, so a difference
  is a finding, not a failure.
- The command, the weights, the Unimod table, the `-b 32` batch size and the default `-t 0.8` are
  M10-08's (deliverable 8). No other checkpoint and no other threshold is tried (M10-08 Q3, Q11;

- The mzML of each run must pass M10-08's `mzml-check` (M1–M8) with that run's
  `acquisition.json` values. A failed check is a route failure on that run (exit 1 of step 1), R9

## `cascadia_convert.sbatch` (step 3)

Header as `scripts/slurm/_header.sbatch`; `set -euo pipefail`, `set -f`. No arguments.
`A3="${A3_OUT_DIR:-$GIAP_ROOT/pilot/A3}"`, `OUT="$GIAP_ROOT/pilot/inputs"`, `GIAP_PYTHON` defaults to
the shared venv's python; giap runs as `PYTHONPATH="$GIAP_REPO/src" "$GIAP_PYTHON" -c 'from giap.cli
import cli; cli()' …` (no `uv run`). In order:

1. **Gate:** `cascadia_convert.py gate` (entry rule 1). Exit 3 is passed through: the job exits 3
   and writes nothing.
2. **Runs:** the run labels come from `validation/pilot/inputs/acquisition.json` in file order
   (`WT_1`, `WT_2`, `WT_3`). For each, `$A3/<RUN>/<RUN>.ssl` exists and is non-empty, else exit 2
   naming it. Its sha256 goes into `$A3/ssl.sha256` (`sha256sum` format, sorted by run).
3. **Per-run L6 check:** `a3_feasibility.py evaluate` on each `.ssl` →
   `$A3/<RUN>/feasibility.json` (M10-08's schema, aggregates only). Exit 0 (pass) and 3 (fail) are
   both recorded; exit 1 or 2 is exit 1 of this job. **Rule fixed before the runs:** if two or
   three runs fail L6, the job stops with exit 3 and the message "L6 fails on <n> of 3 runs: lead
   decision before A3 runs" (question Q2). One failing run is reported and the job continues: all
   three runs are always converted, never a data-chosen subset.
4. **Convert:** `giap convert --from cascadia $A3/WT_1/WT_1.ssl $A3/WT_2/WT_2.ssl
   $A3/WT_3/WT_3.ssl --out <tmp a3.tsv.gz> --source denovo`, stderr to `<tmp a3.convert.log>`. A
   non-zero exit is exit 1; temporary files are deleted and `$OUT/a3.FAILED` is written.
5. **Determinism:** the same command into `$TMPDIR`; `cmp` with step 4's output, else exit 1.
6. **Summary:** `cascadia_convert.py summary --ssl-sums $A3/ssl.sha256 --peptides … --log …
   --acquisition … --out <tmp a3.convert.json>`. Exit 1 on any summary rule failure.
7. **Move into place** (rename) only after 4–6 pass; a stale `a3.FAILED` is removed at the start
   of the next attempt.

Exit codes: 0 converted and checked; 1 L6 evaluation error, conversion, determinism or summary
failure; 2 a precondition; 3 the gate (verdict fail) or L6 failing on ≥ 2 runs.

### `cascadia_convert.py`

- `gate [--feasibility F] [--assets T]`: entry rule 1. Exit 0 pass; 3 verdict fail (prints the
  reason and "M10-10 is skipped; open M10-11a"); 2 missing or malformed file, weights hash
  mismatch.
- `summary`: pure `summarize(ssl_rows, peptides, issues, acquisition_runs) -> dict`, written as
  `a3.convert.json` (sorted keys, 2-space indent, trailing newline, no timestamp outside `job`):
  - `ssl`: per run, path, sha256, bytes, data rows;
  - `outputs`: the peptide table and the log, each with path, sha256, bytes, data rows;
  - `giap` (version, `git rev-parse HEAD` of `GIAP_REPO`, dirty flag), `command` (argv), `job` (id,
    node, start and end UTC);
  - `issues`: code → {severity, rows}, parsed from the log;
  - `counts` over the converted table: `rows`, `rows_per_run`, `distinct_peptides`,
    `distinct_peptides_7_30`, `modified_rows` (`modified_peptide ≠ peptide`), `charge_counts`,
    `score_min`, `score_median`, `score_max`, `score_at_or_below_default_cutoff` (expected 0).

  **Summary rules** (each failure a string in `failures`):
  1. table rows = the sum of the `.ssl` data rows (one output row per input row, M10-09 D4);
  2. `rows_per_run` keys = the acquisition labels exactly (the D1 stems of `file` match the runs);
  3. no error issue; `warn` codes are listed, not failed;
  4. every `source` is `denovo`, and the table has no `q_value`, `pep`, `is_decoy` or `intensity`
     column (M10-09 D3).

  It holds paths, hashes and counts only; no sequence (the test checks that no string value
  matches `^[A-Z]{7,}$`).

## The three-way compare (step 5)

`pilot_compare.sbatch OUT_A1 OUT_A2 OUT_A3 CMP` runs `giap compare OUT_A1 OUT_A2 OUT_A3 --outdir CMP
--labels A1,A2,A3`, then the same into `$TMPDIR/cmp2`, then `run_evidence.py compare CMP --second
$TMPDIR/cmp2 --labels A1,A2,A3 --out pass2/evidence/compare3.json`. Rule set C, generalised to N
labels (N = 2 is M10-04's behaviour, unchanged):

| # | Rule (N labels, P = N(N−1)/2 pairs in label order) | Failure string |
|---|---|---|
| C1 | the three tables exist and pass `check_tsv` | `table:<name>:<message>` |
| C2 | `compare_abundance` has exactly P rows, pairs (A1,A2), (A1,A3), (A2,A3) in that order. The two A3 rows carry `missing_in:A3` (A3 has no intensities): expected, recorded, not failed | `abundance_rows:<n>` |
| C3 | the matrix section has N × G rows, each locus tag once per run | `matrix_rows:<n>` |
| C4 | `compare_stability` has one row per family × pair | `stability_family:<name>` |
| C5 | `compare.html` and `V16_compare.svg` exist, non-empty | `no_compare_report` |
| C6 | `CMP` and `CMP2` tables byte-identical | `nondeterministic:<name>` |
| C7 (N = 3 only) | the (A1, A2) rows of `compare_abundance` and `compare_stability` equal those of `pass1/cmp_a1_a2` | warning `a1_a2_rows_differ:<table>`, not a failure |

C7 is a warning because the bootstrap stream is shared across pairs; with (A1, A2) drawn first it
should hold, and a difference is a finding for M9-22's owner.

A1 and A2 are pass-1 runs at an older commit than A3. `giap compare` accepts that (same genome and
locus tags); the evidence records the three `git_commit`s, and M10-14 re-runs all three arms on one
commit for the frozen report (question Q4).

## Metric 6 (§15.5): novel ORFs and variants by class and confidence, A2/A3 overlap

Computed in `metrics.py` (`m6`) from `tables/novel_orfs.tsv` and `tables/variants.tsv` of each arm,
read with `_table` (schema-checked, 1-based coordinates as written). Pure functions:
`novel_summary(novel_orfs)`, `variant_summary(variants)`, `overlap(a, b, key)`.

**Per arm (A1, A2, A3),** `m6.<arm>`:

- `novel_orfs`: `n_rows`; `by_class` for every class of the schema enum (`nterm_extension`,
  `cterm_extension`, `intergenic`, `cds_outframe`, `antisense`, `pseudogene`, `sorf`), each with the
  confidence buckets `called` (`called = true`), `unestimated` (not called and `class_fdr =
  unestimated`) and `not_called` (the rest); and the same three totals.
- `variants`: for `call = ALT`, counts by `alt_type` (`substitution`, `swap`, `block`,
  `frameshift`) × `confidence` (`high`, `candidate`); `mixed` (count of `call = mixed`); and
  `class_error`: rows with a numeric `class_error_rate` vs `unestimated`. For A3 every row is
  expected `unestimated` (§7.5.4, no spectrum pairing); a numeric value there is a warning
  `a3_class_error_estimated`.

**Overlap A2/A3,** `m6.overlap_a2_a3`:

| Family | Key | Sets |
|---|---|---|
| novel ORFs | (`contig`, `strand`, `end`): the stop codon, which does not depend on the peptides | `called` rows; and, reported beside it, all rows (`any_row`) |
| ALT sites | (`contig`, `codon_start`, `strand`, `alt_aa`): `compare_stability`'s `alt_sites` key | `call = ALT` rows; and the `confidence = high` subset in both arms (`high`) |

For each set: `n_a2`, `n_a3`, `n_shared`, `union`, `jaccard` (`null` with `reason = both_empty`
when the union is 0), `a3_confirmed_by_a2 = share(n_shared, n_a3)` and
`a2_found_by_a3 = share(n_shared, n_a2)` (Wilson 95 %, M10-05's `share`; `null` with
`empty_denominator` at n = 0). For novel ORFs also `class_agree` (shared keys with the same
`class` in both arms) and `by_class_a3` ({class: {n, shared}}).

**Cross-checks:**
- ALT `call = ALT` set must match the (A2, A3) `alt_sites` row of
  `cmp_a1_a2_a3/…/compare_stability.tsv` (same key, same set): `n_a2 = n_a`, `n_a3 = n_b` and
  `n_shared` equal exactly (integers), and `jaccard` equal after formatting both with `%.6g` (the
  TSV writer's float format; never a raw float `==`); `both_empty` must agree with compare's flag.
  Any difference is **`Inconsistent`, exit 1**. Compare reads `codon_start` through `RunView`
  (0-based) and metric 6 reads it as written (1-based); the shift is the same for every row, so
  counts agree, but the cross-check compares counts, never key tuples across the two readers.
- novel-ORF Jaccard is compared with the (A2, A3) `novel_orfs` row (which keys on `orf_id`); a
  difference is the warning `novel_orf_key_differs` with both values. The per-arm counts must
  agree (`n_a2 = n_a`, `n_a3 = n_b`: within one arm `orf_id` and the stop codon are one-to-one);
  a count difference is the warning `duplicate_orf_key` (see "Ties"), not an exit. The stop-codon
  key is the metric; the `orf_id` key can split one ORF in two (see "What exists").

Metric 6 is descriptive. Counts and Jaccards carry no error estimate (R4: the report labels them
"descriptive, unestimated"); only the two shares carry Wilson intervals, and those describe the
sample of calls, not an FDR.

## Hypothesis 4 (§15.7): genome-anchored de novo precision vs precision against A2

**What can be measured here.** "Precision measured against A2 identifications" would be
spectrum-level in a DDA design: a de novo call is right when the same spectrum's database match
agrees. DIA-NN reports no spectrum (no `spectrum_id`; preflight warns `no_spectrum_pairing`), so
that comparison does not exist for this pilot. What exists is **sequence-level confirmation**: a de
novo peptide whose sequence A2 identified at 1 % FDR is, up to A2's own FDR, correct. Unconfirmed
peptides may still be correct (A2 misses peptides, and novel peptides are not in A2's database).
The A2-confirmed share is therefore a **lower bound** on precision, and H4 can be refuted by it
but not confirmed (question Q5).

**Definitions** (all inputs on FarmShare; `h4` in `metrics.json`):

1. **De novo queries** S: `select_queries(aggregate_peptides(validate_peptides(P3, cfg3.input)[0])[0],
   cfg3)` rows with `source = denovo` whose length falls in a `cfg3.mapping.length_classes` class.
   This is the frame the mapping step bins (preflight aggregates before `select_queries` sees the
   table), with the same per-peptide score: the **maximum** over the peptide's rows (§5.3).
   Applying `select_queries` to the validated rows without `aggregate_peptides` would keep the
   first row's score and put peptides in different bins than GIAP's; the label cross-check of
   definition 2 would not catch it (statistician review S1). A test plants one peptide on three
   rows with scores 0.85, 0.99, 0.90 (first row lowest) and checks it lands in the bin of 0.99.
2. **Bins:** `score_bins(score(S))`, the step's own function. Cross-check: the set of bin labels
   equals the `score_bin` values of `out_a3/mapping/mapping_fdr.tsv` `section = denovo_precision`;
   a difference is **`Inconsistent`, exit 1** (the metric would not describe GIAP's bins).
3. **A2 identifications** D2: M10-05's `split_contaminants(P2, cfg2)` set D (accepted target,
   non-contaminant query peptides of A2), I → L folded.
4. Per bin b: `n_b = |S_b|`, `k_b` = peptides of S_b whose I→L-folded sequence is in D2,
   `L_b = share(k_b, n_b)` (Wilson 95 %).
5. Per bin, from `mapping_fdr.tsv`: `genome = {precision, ci_low, ci_high, c_value, flags}`.
6. **Reportable bin:** `genome.precision` not null (not `unreported`) and `n_b ≥ 20`. B = the
   number of reportable bins.
7. **Relations per reportable bin** (statistician review S2: the verdict is a family of B
   one-sided comparisons, Bonferroni within H4; fixed now, before any data):
   - `relation_95` (descriptive, rendered): `below_lower_bound` when `genome.ci_high <
     L_b.ci_low`, both at 95 %; else `consistent`.
   - `relation_adj` (used by the verdict): with z_B = Φ⁻¹(1 − 0.025/B) and z = Φ⁻¹(0.975),
     `U_b = min(1, genome.precision + (genome.ci_high − genome.precision) · z_B / z)` (GIAP's
     percentile upper half-width rescaled to the one-sided 1 − 0.025/B level; the bootstrap
     replicates are not published) and `L_b^adj = wilson_ci(k_b, n_b, level = 1 − 0.05/B)`;
     `below_lower_bound` when `genome.ci_high < L_b^adj.ci_low` (the unrescaled 95 % genome upper
     limit; the pre-registered fallback, adopted 2026-10-25, see "Lead decision: the H4 fallback"
     below), else `consistent`. `L_b^adj` is the two-sided Wilson at `level = 1 − 0.05/B`, whose
     lower limit is the one-sided 0.025/B limit. `U_b` (the rescaled upper limit above) is still
     written, as a descriptive column; it no longer enters the verdict. Both `U_b` and `L_b^adj`
     are written.
8. **Verdict** (pre-registered, no data seen):
   - `not_evaluable`: no reportable bin, or any `denovo_precision` row carries `c_assumed`;
   - `not_supported`: two **consecutive reportable bins** (adjacent in `score_bin` order after
     non-reportable bins are removed; skipped labels from merged ties do not break adjacency) both
     have `relation_adj = below_lower_bound`. With B = 1 the verdict cannot be `not_supported`;
   - `consistent_with_lower_bound`: otherwise. The word `supported` is never used, because only a
     lower bound exists.
9. **Descriptive extras:** the n-weighted mean of `genome.precision` over reportable bins and the
   pooled `share(Σk_b, Σn_b)`, both labelled descriptive; the per-bin `L_b` share among the
   S_b peptides that are in the in-silico tryptic digest of A2's search FASTAs
   (`strain_db.faa.gz` + contaminants, GIAP digest rules, I→L): `L_b_searchable`, which removes the
   novel and non-tryptic calls A2 could never confirm (reported, not used by the verdict).
10. **Caveats** (rendered with the result): the bins span Cascadia's (0.8, 1] only (M10-09
    statistician notes); `c_value` comes from A2 itself, so A2 enters both sides through c_ℓ (a
    shared dependence, not an independent check); the class error rates of ALT calls are
    `unestimated`; plus the dependent-rows and contaminants-in-c_ℓ caveats of the statistician
    review (S3).

## Edge cases

- **M10-08 verdict "fails on timsTOF".** Example 1. M10-10 is skipped and M10-11a is triggered; the
  skip is recorded, not a failure of this issue. 10a is not merged (its jobs are Cascadia-specific;
  the PR is closed with a pointer to the verdict). 10b lands: M10-11b reuses the per-arm metric-6
  summary on UTI89. Its overlap and H4 are `not_evaluable` there, with `reason = "different_strain"`
  (UTI89 vs Nissle: `giap compare` exits 1 on different genomes, ADR-0046; index L9: de novo
  precision `unestimated`).
- **Verdict pass but a later run fails structurally** (WT_2's mzML fails M1–M8, or Cascadia crashes
  on WT_3 after R9): A3 needs all three runs (§15.2 "the same runs"). The lead decides between
  running A3 on fewer runs (reported as a deviation) and M10-11a (question Q2). Never a silent
  subset.
- **Circular vs linear.** All four Nissle replicons are circular. A novel ORF whose stop codon lies
  across the origin has its `end` as written by `novel/outputs.py` (`(stop + 2) % n` on the plus
  strand); both arms use the same rule, so the key matches. A codon that spans the origin keys on its
  `codon_start` as written. Linear replicons need no special case. CI fixtures include one
  origin-spanning ORF in both arms (shared) and one on a linear contig.
- **Minus strand.** The ORF key carries `strand`; for minus-strand ORFs `end` is the stop codon's
  lowest coordinate (`o.stop`). Two ORFs on opposite strands with the same `end` are different keys
  (fixture). ALT sites on the minus strand key on `codon_start` and `strand` as compare does.
- **Empty input.**
  - A header-only `.ssl` for one run: the converter gives info `empty_input`; the per-run L6
    check says `fail` (`too_few_peptides`), so the run counts toward the "≥ 2 of 3" rule. All three
    header-only: `empty_table`, exit 1 at step 4 (and the L6 rule already stopped it with exit 3).
  - `novel_orfs.tsv` or `variants.tsv` with no data rows in an arm: zero counts; overlaps with
    `both_empty` or `empty_denominator`; not a failure. A table absent in an arm (module off):
    `reason = missing:<table>` for that arm, as M10-05 does.
  - No `denovo_precision` rows: rule A10 fails the A3 run (`no_denovo_precision`); H4
    `not_evaluable`.
  - `D2` empty (A2 accepted nothing): `k_b = 0`; every `L_b` is 0 with its CI; H4 can only be
    `consistent_with_lower_bound` or `not_evaluable`; a warning `a2_empty`.
- **Ties.**
  - Scores: tied scores share a bin (`score_bins` merges equal edges), so there may be fewer than
    10 bins; the cross-check of definition 2 compares labels, not a fixed count.
  - The same peptide on several rows (charges, runs): one query, the maximum score over its rows
    (§5.3 aggregation, as the step sees it; definition 1).
  - Jaccard ties: none possible; set operations only.
  - An ORF key present twice in one arm's table (impossible by construction): counted once, warning
    `duplicate_orf_key`.
  - Two ALT residues at one codon: different `alt_aa`, different keys, as in compare.
- **I/L.** Cascadia writes L only; DIA-NN may write I. H4 folds I→L on both sides; metric 6 keys
  are coordinates, not sequences.
- **Contaminants.** A3 de novo peptides that are contaminants are not in D2 (contaminant-only
  peptides are removed from D2), so they count as unconfirmed; `L_b` stays a lower bound.
- **A2's FDR.** D2 is at 1 % FDR; a lower bound computed from it can be off by up to that share.
  Stated in the caveats, not corrected.
- **Commits differ between arms.** A1/A2 (pass 1) and A3 (pass 2) ran different commits: recorded,
  warned (`giap_commit_differs`, as M10-05), not failed.
- **GPU nondeterminism.** The WT_1 re-run may differ from the smoke run; only the M10-10 run feeds
  A3.
- **Disk.** Three mzML of ≈ 1–4 GB each and small `.ssl`; `out_a3/work` tens of GB (M10-14 cleans).
  `du -sh` of `$GIAP_ROOT/pilot/A3` and `runs/pilot/pass2` goes to PROGRESS.

## Statistician notes (for the review of H4)

- The A2-confirmed share `L_b` is a lower bound on the bin's precision up to A2's FDR (≤ 1 %), so a
  CI-separated `genome.ci_high < L_b.ci_low` is evidence that the genome-anchored estimator
  underestimates that bin. *(Superseded by the statistician review, S2: the bound holds pathwise
  on the realised share, the valid per-bin guarantee is the genome CI's one-sided miss rate (≤
  2.5 % at 95 %, not ≈ 0.6 %), and the verdict now uses the Bonferroni-scaled `relation_adj` of
  definition 7, fixed before any data.)*

  "consistent with the A2 lower bound", never "agrees".

### Edited in the spec

- **S1 (blocking, fixed: definition 1, "What exists", "Ties", finding 2).** H4's query frame
  applied `select_queries` to the validated *rows*. The step does not: preflight writes
  `peptides.norm.parquet` from `aggregate_peptides` (one row per stripped peptide, `score` =
  max), and `select_queries` reads that, so its `drop_duplicates` is a no-op and GIAP's bins use the
  **maximum** score. Spec-writer finding 2 was therefore wrong about the step, but right that a
  first-row score biases the bins: had H4 used it, peptides seen in several runs (mostly correct
  ones: a correct peptide is read several times, a wrong one usually once) would have moved to
  lower bins than GIAP put them in, so `L_b` and `genome.precision` would describe different
  peptide sets, raising `L_b` in low bins and lowering it in high ones. That is a spurious
  `below_lower_bound` exactly where the genome estimate is lowest. The label cross-check of
  definition 2 cannot detect it (labels are 0…k−1 either way). Definition 1 now aggregates first; a
  test plants a three-row peptide whose first row has the lowest score.
- **S2 (blocking, fixed: definitions 6–8, example 11, statistician notes).** The bound itself is
  valid, but the error-rate argument for the rule was not. (a) `k_b ≤` the number of correct
  peptides of S_b, pathwise, up to A2 false confirmations (below), so `L_b ≤` the realised bin
  precision, which is the estimand of `genome.precision` (methods › Estimand). Hence a false
  `below_lower_bound` needs `genome.ci_high <` the realised precision: its per-bin rate is bounded
  by the genome CI's one-sided miss rate, ≤ 2.5 % at 95 % when calibrated, not "≲ 0.6 %". The two
  intervals are not independent intervals around ordered means; k_b and the genome estimate share
  the bin's correct peptides. (b) A scratch simulation with the real `denovo_precision` (10 bins,
  p 0.30…0.99, R = 200, A2 confirming every correct peptide, the worst case for the bound) gave
  family-wise false `not_supported` 0.000–0.005 with independent rows, but **0.165–0.175 with
  runs of 5–10 dependent rows** (c − r = 0.2 or n = 2000/bin), the dependence that the methods
  note already documents (the bootstrap CI is too narrow). The Bonferroni-scaled rule cut that to
  0.065–0.075, and to 0.005 with 400 per bin. The notes' plan to switch to Bonferroni only "if
  the attack exceeds 0.05" is a data-free choice either way; the edit fixes it now:
  `relation_adj` (verdict) uses U_b with the upper half-width rescaled to 1 − 0.025/B and Wilson
  at 1 − 0.05/B; `relation_95` stays descriptive. The rescaling assumes a near-normal upper tail of
  the bootstrap; the attack measures it.
- **S5 (should-fix, fixed: metric 6 cross-checks).** The ALT cross-check compared Jaccards as
  floats, but `compare_stability.tsv` is written with `%.6g`. It now compares `n_a`, `n_b` and
  `n_shared` exactly and the Jaccard after `%.6g`. Compare reads `codon_start` 0-based
  (`RunView`) while metric 6 reads it 1-based as written, so key tuples must not be compared across
  the two readers. The novel-ORF check also compares per-arm counts (warning only).

### Open findings

- **S3 (should-fix, definition 10 caveats).** Add two rendered caveats. (i) **Dependent rows:**
  nested or overlapping Cascadia peptides of one locus share correctness and target-match status;
  GIAP's bin CI is then too narrow, and a `not_supported` can come from that undercoverage rather
  than a biased estimator (S2 (b): the adjusted rule still reaches ≈ 0.07 at 2,000 per bin with
  runs of 5). Report per bin the descriptive `nested_share`: the share of S_b peptides that are a
  substring of another peptide of S (I→L folded), so the reader can see how clustered the bin is.
  (ii) **Contaminants in c_ℓ:** `c_by_class` counts every accepted A2 target row, contaminant
  rows included. Those never match the genome, so they lower c_ℓ, which biases `genome.precision`
  **up** (c_ref < c_true, the methods note's anti-conservative direction for π̂). For H4 that
  makes `not_supported` *less* likely (lower power), not a false refutation. State the A2
  contaminant-row share beside c_value. Correct de novo contaminant peptides are excluded from
  D2 and count as wrong in the genome estimate, so they affect both sides in the same direction.
- **S4 (should-fix, definition 9).** `L_b_searchable` is not a lower bound on bin precision. It
  is the A2 confirmation rate among the searchable de novo peptides, a product of A2's
  sensitivity and the de novo precision of a subset, so the report must not set it beside
  `genome.precision`. Label it "A2 confirmation among searchable peptides (descriptive)". Name the
  digest settings (GIAP's digest rules are not DIA-NN's: missed cleavages, the 7–30 length window,
  N-terminal Met excision) and the input: the CLI has no option for `strain_db.faa.gz`. Add one
  (`--search-fasta`), or reuse M10-05's metric-3 digest input if it already carries that FASTA.
- **S6 (should-fix, definition 2).** The label cross-check is weak: `mapping_fdr.tsv` has no
  per-bin n, so a wrong query frame with the same number of distinct edges passes. Also check
  |S| against the de novo query count of the run's placement log record ("placement: N queries (M
  de novo)"; with the default 7–40 window every de novo query has a length class, so M = |S|).
  Make it `Inconsistent` when the record is found and differs, and a warning
  `denovo_count_unchecked` when it is not found. A `BinPrecision.n` column in `mapping_fdr.tsv` would
  be the clean fix; that is a backlog item for the M3 owner, not this issue.
- **Validity of the lower bound, the other points (no change needed).**
  - *A2 false positives:* a false confirmation needs a wrong de novo string that equals a peptide
    A2 also accepted wrongly. A2's false identifications are database peptides absent from the
    sample, so the coincidence rate is well below A2's 1 % (conditioning on a de novo match
    enriches for true IDs). The exception is correlated errors on near-isobaric pairs (GG/N,
    deamidation N→D, Q/K), which are small. The existing caveat ("off by up to that share") is
    conservative enough.
  - *Peptides A2 cannot detect* (novel, non-tryptic, variant, outside DIA-NN's mass or charge
    window): they only loosen the bound.
  - *I/L:* folding on both sides matches GIAP's I = L correctness. Folding can merge two A2
    peptides, which is harmless for a membership test.
  - *Modifications:* both sides compare stripped sequences, which is GIAP's unit (§5.3), so a
    mislocalised or wrong modification on the right backbone counts as confirmed (correct by
    GIAP's estimand). A mass-equivalent wrong residue (N+deamidation called D) is a different
    string and counts as unconfirmed; the bound holds.
- **Verdict names (no change).** `not_supported` / `consistent_with_lower_bound` /
  `not_evaluable` are sound for a one-sided bound. `not_evaluable` on any `c_assumed` row is right,
  since c_ℓ = 0.99 is not A2-calibrated. One addition (nit): when B ≥ 1 but every reportable bin
  has `genome.ci_high = 1` (clipped), state that no refutation was possible in those bins.
- **Wilson (no change).** `wilson_ci` reproduces every number in examples 9 and 11 to 4 decimals
  (checked: 1/3 → [0.0615, 0.7923]; 1/2 → [0.0945, 0.9055]; 120/200 → [0.5308, 0.6654], at 0.995
  [0.5008, 0.6917]; 90/150 → [0.5200, 0.6750], at 0.995 [0.4855, 0.7046]). The Wilson interval
  treats k_b as binomial around a super-population confirmation rate, while `L_b` bounds the
  realised share exactly. Using its `ci_low` is therefore conservative, not required for
  validity, which is acceptable.
- **Metric 6 (no change beyond S5).** The stop-codon key (`contig`, `strand`, `end`) is
  peptide-independent on both strands, origin-crossing included (`(stop + 2) % n` on `+`,
  `o.stop` on `−`, `novel/outputs.py`). For ORFs open at a linear 3′ end (`partial`) the key is
  the last full codon, also peptide-independent. Nit: the `high` set should say it is A2's `high`
  rows vs A3's `high` rows (each arm's own confidence), `n_shared` their intersection. The two
  shares' Wilson intervals treat calls as iid; they are labelled descriptive, which is correct
  (R4).
- **Families (§8.1/§8.2).** H4 is not an §8.1 claim; its only family is the B per-bin
  comparisons, controlled by Bonferroni (S2). Metric 6 forms no p or q. No p-value is formed
  anywhere here, so the §8.2 effect-size rule is met by the per-bin `L_b`, `genome.precision`
  and their intervals.

### Attack plan (`tests/calibration/attacks/test_attack_h4_lower_bound.py`, statistician, 10b)

Written by the statistician after `hypothesis4` exists (it calls the real `denovo_precision` and
the real `hypothesis4` verdict, never a re-implementation). Marked `calibration` (fast, R = 200)
and `calibration_full` (R = 1,000); seeds from `giap.rng.for_step("attack_h4", seed)`. Criterion

Each replicate plants 10 score bins with true per-peptide correctness p_b = 0.30 … 0.99, one or two
length classes with known c_true and decoy rate r. A correct peptide matches the target with
probability c_true, a wrong one with r. The reference c_ℓ is drawn from n_ref = 2,000 reference
peptides at c_ref. A2 confirms each correct peptide with probability φ and each wrong one with
probability ε.

| Scenario | Plant | H4 | Gate |
|---|---|---|---|
| `worst_case` | φ = 1, ε = 0, n = 2,000/bin, c_ref = c_true = 0.95, r = 0.08 | true | FWER |
| `small_bins` | as above, n = 25/bin (just over the n ≥ 20 rule) | true | FWER |
| `low_denominator` | c_true = c_ref = 0.6, r = 0.4 (c − r = 0.2), φ = 1 | true | FWER |
| `partial_confirm` | φ = 0.6, n = 500 | true | FWER |
| `a2_false_confirm` | φ = 1, ε chosen so false confirmations are 1 % of k_b | true | FWER |
| `ties_and_reps` | each peptide on 1–3 rows with scores whose first row is the lowest; scores tied at the top (Cascadia's (0.8, 1]) so bins merge | true | FWER, and bins equal GIAP's (S1) |
| `contaminants` | 5 % correct contaminant peptides (no target match, not in D2); reference with 3 % contaminant rows | true (direction: lower power) | FWER |
| `clustered` | runs of 5 peptides sharing correctness and target match, φ = 1 | true | **reported, not gated** (the documented CI limit, S3); the measured rate goes into the methods table |
| `power_easy_reference` | c_ref = 0.99 > c_true = 0.85 (estimator biased down by ≈ 0.15) | false | power reported (expected > 0.8 at n = 500) |
| `power_one_bin` | one bin's genome precision biased down by 0.2 | false | power reported |

The test also asserts that the verdict is never `supported`, and that `relation_95 ⊇
relation_adj` (every bin below at the adjusted level is below at 95 %). If a gated scenario fails,
the merge blocks (§8.5). The fallback, fixed now, is to drop the rescaled U_b and require
`relation_adj` in **two** adjacent bins.
