Bakta, miniprot and tblastn now run with the genetic code set by `annotation.translation_table`: Bakta gets `--translation-table` at tables 4 and 25 (its command line at table 11 is unchanged), miniprot indexes the genome with `-T <table>`, and tblastn gets `-db_gencode <table>` appended to `mapping.proteins.tblastn_args`. The default `mapping.proteins.tblastn_args` is now `-seg no -evalue 1e-5` and no longer contains `-db_gencode`; a `-db_gencode` equal to the table still works, and any other value stops the run. A precomputed Bakta annotation JSON that records a different translation table is refused with an input error (exit 1). `annotation_meta.json` and the run manifest's `annotation` block record `translation_table` (output schema version 1.1). The report's Methods section names the genetic code of every run, and at tables 4 and 25 the summary opens with a note on how TGA is read.
